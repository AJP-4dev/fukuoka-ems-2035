# 福岡市 救急需要の未来地図 2025→2035 — 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 福岡市 7 区の救急出場件数を 2025〜2050 年・3 シナリオで推計し、横浜版をフォークした単一 HTML の 3D レポート（10年モード／長期モード、署所別負担、整備指針の基準隊数）として GitHub Pages に公開する。

**Architecture:** Python の小さなビルド段（転記 JSON → `src/build_trend.py` → `src/build_model.py` → `data.js` → `src/build_html.py` → `index.html`）と、横浜版 `template.html` を改修したフロント（Three.js r128、データは `const DATA` 埋め込み）。入力データはすべて `src/*.json` に転記し、pytest で元資料の合計と一致することを検査する。生データ（PDF/xls/xlsx）は `src/raw/` に置き gitignore。

**Tech Stack:** Python 3 venv（pymupdf, openpyxl, xlrd, pytest, shapely）、Three.js r128（横浜版と同じ CDN）、GitHub Pages。

**Spec:** `docs/superpowers/specs/2026-10-23-fukuoka-ems-design.md`（本計画はこの設計書の §番号を参照する。実装者は両方を読む）

## Global Constraints

- 空間単位は福岡市 7 区（東・博多・中央・南・城南・早良・西）。市外分は除外して区計を取る（設計 §2）。
- 年は 2025〜2050 の各年。10年モード = 2025〜2035、長期モード = 2035〜2050（設計 §7）。
- 年齢帯は 6 つ、キーは固定：`k`=0–6 歳, `j`=7–17, `w`=18–64, `e1`=65–74, `e2`=75–84, `e3`=85+（設計 §5.2）。`GROUPS=['k','j','w','e1','e2','e3']` を Python・JS 両方で使う。
- シナリオキーは `L`（下限・人口変化のみ）/ `M`（中間・コロナ前トレンド継続、2040 年で頭打ち）/ `H`（上限・全期間トレンド継続）（設計 §5.3）。
- 人口は全シナリオ共通。シナリオ差は利用倍率のみ（全年齢一律）。
- 昼間補正係数 `DAYF=0.35`、按分キー = 夜間人口×0.65 + 従業地人口×0.35（設計 §5.1, §5.6）。
- 整備指針：基準台数 = (救急需要人口 − 100,000) ÷ 50,000 + 5、係数は福岡実測（帯別搬送率 ÷ 全年齢搬送率）（設計 §5.5）。
- 横浜版の `RANGE_LATE` / `isLate()` による暗黙の尺度切替は持ち込まない（設計 §7）。
- 推定値（年齢 6 帯、署所別負担、署所別到着時間）は画面上で「推定」と明記する（設計 §3）。
- **出典と計算法の見せ方（ユーザー要件 2026-10-23）**：すべてのグラフ・地図指標・カード数値の直下に「出典：資料名（年）」の 1 行を置く。方法ページは「式を文章で → 図解 → 実例の数字で 1 区を手計算」の 3 段で書く（横浜版 v3 の方法ページの型）。借用値（全国の高齢者内比率・0.35・横浜の到着時間回帰）は「借りた値」節にまとめ、なぜ借りたかを 1 文ずつ付ける。画面内の「?」で式と出典がその場で開く。
- Git：ローカルリポにタスクごとにコミットしてよいが、**GitHub へのリポ作成・push・Pages 公開はユーザーの動作確認と承認の後**（AGENTS.md 承認フロー）。コミットメッセージ末尾に `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`。
- 言語：画面文言・コメント・コミットは日本語。用語は平易に（「出場件数/千人」など横浜版 v6.2 の表記を踏襲）。
- ダウンロードした PDF/xls は `src/raw/` に隔離し、読むスクリプトは `src/` に置き、`python -I` で実行する。

## Review Focus

1. **区別推計 PDF の表が年で分割されている**（2020〜2034 と 2035〜2050 が別ページ・別ブロック）。年の取り違えや欠落 → Task 2 のテストで「各区 31 年 × 19 帯がすべて埋まり、区計の合計が全市表と一致」を検査。
2. **R6 年報の区別出動件数が表ではなく図（画像）**。構成比しか読めない可能性 → Task 4 で「区の合計 + 市外 = 100,181」を必須にし、構成比から逆算した場合は `nenpo_inputs.json` の `_note` に明記してテストが読む。
3. **救急隊が配置されていない出張所がある**（第1-4-2表に冷泉・花畑・室見・笹丘などが無い）。隊 0 の署所で 0 除算や「隊あたり ∞ 件」 → Task 9 で隊 0 署所は担当人口を最寄りの隊あり署所に移し、カードに「救急隊なし」と出す。テストで `units==0` の署所は `load==0`。
4. **福岡は 2040 年ピーク後に減る区がある**。増減率が負になり、発散スケールの負側と飽和が要る → Task 10 で `colorPct(-45)` が負側の端色を返すテストを置く。
5. **2025 年の基準人口（登録人口）と推計人口 2025 年値のずれ**。横浜版は実績で置換＋推計の変化率を掛ける方式 → Task 8 のテストで `pop[2025]` の区計が登録人口と一致し、`pop[2026]/pop[2025]` が推計の変化率と一致することを確認。
